SPRKKR

class ase2sprkkr.sprkkr.calculator.SPRKKR(label=None, directory='.', atoms=None, potential=None, input_file=True, output_file=True, potential_file=True, input_parameters=None, options=None, print_output=None, mpi=None, empty_spheres=None, executable_suffix=None, executable_dir=None, profile=None, executor=None, project=None, **kwargs)[source]

ASE-facing calculator for SPR-KKR.

SPRKKR is a mutable facade holding defaults shared by calculations: structure/potential, input parameters, filename templates, working directory and execution policy. Preparation snapshots run-specific configuration and materializes the selected physical state into independent calculation files.

Selected Atoms and Potential objects are mutable physical working state, not per-run snapshots. This applies both to calculator defaults and explicitly supplied objects: preparation may promote or normalize the structure, add automatic empty spheres, and synchronize the potential. Once preparation finishes, the returned PreparedCalculation owns its concrete files and resources, so execution no longer depends on subsequent changes to those physical objects.

A calculator instance is not intended to be prepared concurrently from multiple threads because filename-template counters and physical preprocessing are mutable state. Prepared runners themselves own independent resources and may run concurrently.

Materialize current calculation state into one prepared calculation.

InputParameters are copied before one-shot task/options and generated file values are applied. Selected Atoms and Potential objects are not deep-copied and may be normalized or synchronized during preparation. The returned PreparedCalculation owns all concrete files and temporary directory resources, so subsequent physical-state changes do not alter the already materialized run. Call PreparedCalculation.close() when the object is not transferred to a runner.

Materialize SPR-KKR input files without starting an executable.

Preparation always works on an independent snapshot of InputParameters; generated POTFIL/DATASET values therefore never mutate calculator defaults or caller-owned parameter objects.

False as input_file or potential_file requests a managed named temporary artifact. Temporary artifacts are useful for an executing runner, but save_input cannot return ownership of a temporary POTFIL because its public tuple exposes only the pathname. Supply a persistent POTFIL name when return_files=True.

directory=False is intentionally rejected here: a temporary directory is owned naturally by a runner, whereas returning filenames from save_input after deleting their directory would be invalid. Use create_run()/calculate for temporary run directories.

Prepare a calculation and return an unstarted owning runner.

An explicit per-run executor has highest precedence. Otherwise an explicit per-run profile selects its backend; if neither is supplied, the calculator-level executor (when present) overrides the calculator profile backend.

error_file=None stores stderr next to stdout as <output>.err. error_file=True deliberately merges stderr into output_file; False requests a managed temporary stderr file, and an explicit path or file object stores stderr there instead.

callback is a terminal runner callback. It can therefore be invoked with a partially populated result when backend execution or parsing fails. read_callback observes streamed stdout/stderr.

calculate(atoms=None, properties=('energy',), system_changes=['positions', 'numbers', 'cell', 'pbc', 'initial_charges', 'initial_magmoms'], input_parameters=None, potential=None, input_file=None, potential_file=None, output_file=None, directory=None, create_subdirs=False, empty_spheres=None, mpi=None, options=None, task=None, print_output=None, read_callback=None, executable_suffix=None, callback=None, executable_dir=None, gdb=False, profile=None, executor=None, project=None, restart_scf=False, error_file=None, metadata=None)[source]

Run one SPR-KKR task synchronously and return its parsed result.

properties and system_changes are accepted for ASE compatibility. SPR-KKR execution is task-oriented, so properties does not select a different backend task and system_changes is not used for incremental updates; each run materializes the complete supplied calculation state. Per-call mpi, executable_dir and executable_suffix values are immutable overrides of the selected execution profile.

The callback of this synchronous convenience method is intentionally a success callback: it runs only after the result has updated calculator state. This differs from the lower-level terminal callback accepted by create_run(). An unsuccessful execution raises ASE’s CalculationFailed before updating calculator state.
